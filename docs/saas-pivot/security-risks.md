## Known enforcement boundary

Public Store HTTP routes deep-gate Cart, shipping, payment, and completion. Project-owned hooks gate hook-capable Medusa workflows. Installed core workflows without a usable hook remain trusted internal surfaces, including line-item deletion, payment-collection creation, payment-session creation, and shipping-price calculation. A future direct import can bypass HTTP unless it uses an explicit guarded wrapper; code review and a central wrapper policy are still required before production.

The promotion workflow deliberately skips an empty code list used by Medusa during Cart bootstrap before Store-Cart linking. Non-empty internal promotion mutations and public HTTP mutations are gated. This is a narrow internal bootstrap exception, not a general authorization bypass.

## Remaining contract and production risks

- Setup pins a versioned derived policy from one completed provisioning record into both a canonical SHA-256 digest and safe request snapshot. The digest is stable across authentication/session secret rotation. Retry/completion re-resolve and compare the policy. Immutable-policy-pin focused units pass 2 suites/9 tests. A future mutable policy/update workflow still requires a separate explicit contract rather than weakening that immutability.
- Identity provisioning is different: its normalized input contains an initial password, so its replay fingerprint must stay keyed. It currently selects a vendor/JWT/cookie session secret as the HMAC key; secret rotation or priority changes can alter the fingerprint and strand unfinished/replayed operations. A dedicated versioned provisioning-fingerprint key/key-ring plus rotation and migration procedure is a production blocker.
- `disabled` readiness and `cancelled` setup are reserved schema states without transition logic.
- Expired-lease attention has no operator-resolution route, monitoring, or repair UI.
- The focused suite dynamically injects a Shipping Option failure; it is not exhaustive failure injection for every setup checkpoint.
- Final guarded-local backend regression passed 23 suites/144 tests (62 unit, 10 module, 72 HTTP). Backend and all frontend typecheck/lint/build checks, storefront Vitest 3 files/11 tests, SaaS generate/no-change, the unchanged Phase 3A harness, and the Phase 3B guarded harness passed.
- Local `manual_manual`/`pp_system_default` evidence is not production provider, settlement, refund, tax, carrier, credential, or webhook evidence.
- Shared rate limits, shared locks/events, telemetry, alerting, backups/restore, DNS/SSL/deployment, billing, and incident operations remain required.
- The previously exposed Neon credential rotation is unverified. Production migration remains blocked and Neon must not be used for local verification.
- Phase 3A and the bounded Phase 3B pilot are implemented in the current uncommitted working tree. Store currency on vendor Product writes is server-derived and mismatch-tested; exact public capability/purchase DTOs and hostile Store A/Store B checkout/Order isolation passed. Phase 3B's distinct physical-keyboard journey remains pending, so its gate is open.
- Phase 3B persists only the opaque Cart ID in same-origin session storage and keeps customer details in memory. Customer accounts, public Order lookup, production providers, money movement, tax, refunds, notifications, and deployment remain absent by contract.
